## 2026-11-12 (목) — 04 DB 스키마 · 시더 · 초기화 API

- **범위 결정(사용자 "기본안대로")**: 원본 5개 표만 만든다. 미수채권 146행을 전부 저장하고 고객 채권은 `agency_id` 를 비운다. 장려금 `status` 첫 값은 승인→지급완료 · 반려→반려 · 미지급→미접수 [가정]이고 원본 값은 `original_*` 에 보존한다. ERD(`docs/architecture.md`)를 여기에 맞췄다.
- **Step 3 에서 근거를 정정한 곳 두 군데**: ① `check_same_thread=False` 는 SQLAlchemy 2.0 이 파일 DB 에 알아서 넣는다 → `connect_args` 를 뺐다. 스레드 테스트로 확인했다. ② "루트 INFO 면 SQL 이 찍힌다"는 틀렸다. SQLAlchemy 는 스스로 WARNING 으로 고정한다. 그래서 `app` 로거만 여는 이유를 httpx 로 바꿨다.
- **설계 중 잡은 함정**: 상태 변환을 `drop_all` 뒤에 두면 원본이 틀렸을 때 DB 가 지워진 채로 멈춘다 → 변환을 앞으로 옮겼다. 순서를 되돌리면 실패하는 테스트로 증명했다. 빈 표에서 `objects[0].__tablename__` 이 IndexError 를 내는 문제는 (모델, 객체들) 짝으로 피했다.
- **Step 4**: 스크래치패드에서 검증한 1~4단계 정답(소스 13 · 테스트 5)을 그대로 반영했다. ruff 통과, pytest 60개 통과. 사용자가 미리 타이핑한 변경은 없었다. 커밋 · 푸시는 사용자 몫이고, Git 명세서를 전달했다. 로컬 Docker 빌드는 확인하지 않았다.
