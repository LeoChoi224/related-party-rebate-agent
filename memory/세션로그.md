## 2026-11-11 (수) — 문제 분석 · 업무 선택 · 설계 · 환경 준비

- **문제 분석**: 참가 페이지와 A01 · A03 · A04 · A05 를 읽고, 8개 업무의 안내와 데이터를 비교했다. W01 · W03 · W05 · W07 은 데이터를 직접 계산해 봤다.
- **업무 선택 W07**: G1(D-011 · D-024 · D-037)이 1~5월 매달 한도를 넘었는데, 개별 건이 모두 200만원 이하라 전결로 지급된 사례가 데이터에 있다. 규칙이 숫자로 떨어져 4일 안에 핵심 흐름을 끝낼 수 있다고 봤다. 2순위는 W03.
- **설계안 v0.1 → v0.2**: 처음에는 AI 를 체인 3개(해석 · 초안만)로 설계했다. 사용자가 규정 문구("자동 확정하지 않고 상신")를 근거로 "AI 판단 + 사람 최종 결정" 구조를 제안했고, LangGraph 로 바꿨다. 다만 결재 경로는 코드 가드를 남겼다. 이유: AI 가 합산을 놓쳐 전결로 분류하면 잘못된 결재권자가 결정하게 되는데, 1~5월 사례가 바로 그 문제다.
- **스택 결정**: FastAPI + React(Vite)(D안). 빌드가 하나 더 붙는 비용보다 역할별 화면 구성과 React 경험을 택했다.
- **되돌린 일**: 요청 없이 `git init` · 폴더별 `.gitignore` · 상태 다이어그램을 만들었다가 지적받고 되돌렸다. → CLAUDE.md §4 "요청한 범위만 한다"로 규칙화.
- **뼈대**: backend .py 80개, frontend src 47개(설명 주석만), 폴더별 `.gitignore`(사용자 요청 후).
- **AXHub**: CLI 설치(`~/.zshrc` 를 건드리지 않으려고 PATH 등록을 끔), 플러그인 설치, 로그인을 마쳤다. 조회 결과: lounge 는 Axhub 저장소만 허용, Docker · compose · static 지원, 배포 방식은 생성 후 변경 불가.
- **CLAUDE.md**: JARVISEO 내용을 이 프로젝트에 맞게 고쳤다. 대회 규칙 절 추가, 커밋 · 푸시 · 코드 올리는 axhub 명령은 사용자가 직접.
